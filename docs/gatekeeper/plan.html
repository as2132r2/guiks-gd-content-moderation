措辞纪律

不说「安全」——会被听成内容安全（易盾/天御那个红海），而且是防御性的。 广电要的是敢发、发得快、出了事说得清。
不说「敏感词过滤」——九十年代的技术印象。入口那一层叫「入口准入」，判定的不是词，是这次调用该不该发生。
不说 AuditGate——英文、技术词，对这个评委席先天弱一档。代码目录 audit-gate/ 保持不动，赛后再改。
不假装审校是空白——方正智能审校 21 类 136 个词库，黑马校对卖了三十年。主动承认，再讲我们看得见而它们看不见的那一面。

内核

三句话，因果闭环

核心主张

AI 让内容生产提速十倍，但三审三校的人力审核跟不上——提速的结果不是快，是审核堵死，或者放水出事故。

所以我们在同一条链路上做全流程监控：把机械的校对自动化，把判断留给人，把每一步留痕。

让 AI 提速出来的产能，真的能安全地发出去。

为什么必须是因果，不能是并列

「我们用 AI 辅助生产，同时做全流程监控」——这个说法撑不住。评委会问一句很自然的话： 那我能不能只要你的生产部分？ 只要这两半能拆开卖，它们就还是两个产品， 我们又回到了「两个半成品」。

并列（弱）

AI 辅助生产 + 全流程监控。监控是额外做的一层安全，是成本项，可以被砍掉、可以外购、可以换成易盾。

因果（强）

AI 提速 → 审核成瓶颈 → 所以必须自动化校对。监控是产能得以释放的前提，是价值项，拆掉它 AI 提速根本不成立。

县级台原来一天出五篇稿，三个人的三审审得过来。AI 让编辑一天能出五十篇——审核环节当场变成瓶颈。 这时候只有两个结局：要么卡死（AI 白提速，产能堵在终审），要么放水（领导来不及看就签字，出事故）。 监控的真正价值不是防止出错，是让审核跟得上生产的速度。

「安全」这个词不上台

两个原因。一是它太容易被听成「内容安全」，那是易盾、天御那个红海，评委一秒就归类了； 二是它是防御性的——而广电最不缺防御手段，最简单的防御是不用 AI。 广电要的是三件事，用他们自己的话说：敢发、发得快、出了事说得清。

转向一 · 叙事

「那为什么不用内部大模型」

这是台上必然会被问的问题，也是原叙事的致命伤。现实比想象的更不利： 这些行业不是不用内部模型，是早就在买私有化部署了—— 智谱、DeepSeek、讯飞、华为昇腾那套，「数据不出域」是招标文件第一条。 评委里只要有一个懂政企采购的，「防泄漏」这个卖点当场就没了。

私有化解决了「模型在哪」，没解决这四件

  1. 数据不出域 ≠ 内部不越权，而且私有化让它更严重。 内部模型的价值来自接内部知识库，一接上模型就有了全量数据读取权。传统权限体系在 RAG 面前是失效的—— 向量检索不认部门墙。泄密对象从「外部 API 厂商」变成「自己人」，而后者没有任何现成系统在管。
  2. 幻觉和内容违规不因为模型跑在内网就消失。 广电播出内容出问题，罚的是台，不管推理发生在哪台机器上。而且私有化部署受限于本地算力， 往往是参数更小、对齐更弱的版本，违规概率比调用旗舰 API 更高——这一项上私有化是负分。
  3. 「可追溯」本身是监管要求，而私有化交付的是模型，不是审计链路。 厂商给的是推理服务和一个对话界面。谁在什么时间、用什么 prompt、碰了哪些数据、输出被谁拿走了—— 这套留痕得自己建，标里没有。合规责任压在服务提供者身上，压不到模型厂商头上。
  4. 企业的真实形态不是「一个内部模型」，是一片影子 AI。 私有化一体机只管官方那条路。同时发生的是各部门自开的外部 API、办公套件自带的助手、 员工桌面上的各种工具、外包接进来的 SaaS。治理点必须在流量层，不在模型层—— 这恰好是「改一行 base_url 就接管」这个形态真正成立的地方。

还有一层：内部自用确实没人管，但输出会离开对话框

企业内部自用的模型，外部监管的确盯不到，这也是他们敢放开用的原因。但是—— 广电的产出要播出去，能源的产出要进生产系统，白酒的产出要进配方和质检。 输出一旦离开对话框、进入业务流程，责任全都回来了。审计的锚点就在这一刻，和模型部署在哪毫无关系。

台上的一句话版本

私有化解决了「模型在哪」，没解决「模型被谁怎么用、说了什么、该不该说」。 前者是采购问题，后者是治理问题，而后者现在没人管。

转向二 · 审计对象

从保密审计到适播审计

原来审的是什么（读代码得出，非 PR 描述）

对象是一次「请求—响应」交换里的纯文本，双向扫。

  • 入向 scanRequest() 只做一件事：拿用户输入匹配一张约 21 条的提示注入词表 （忽略之前、开发者模式、解除限制、system prompt、原始指令 等）， 命中即 high 级 injection。
  • 出向 scanResponse() 找的全是泄漏：预埋的服务密钥、系统提示词标记、 内部机密（代码注释写的是「定价 / 工艺」）、银行卡号，再加正则扫手机号 / 身份证号 / 银行卡号。
  • 行为是三档动作 block / redact / flag，按每企业策略配置。 redact 是正则打码，block 整段换成固定话术，放行清单里的人降级为只留痕。
  • 红队 probe 六类：prompt-exfil、data-exfil、pii-dump、 jailbreak、role-override、hallucination。 评分五维：可审计性 / 注入抵抗 / 数据合规 / 配置卫生 / 稳健性。

一句话：这是一套「保密审计」，它问的是「不该出来的东西，出来了没有」。

广电问的是另一个问题

广电不问「泄没泄」，问的是「这段内容能不能播」：导向、事实准确、敏感人物与事件、 AI 生成内容标识、版权、用词规范。这两者的差别不是程度，是类别—— 一个是保密（confidentiality），一个是适播（content compliance）。

难点：正则题与判断题

禁用词和一致性能用正则抓；导向和事实准确抓不了，只能用模型判。后者意味着慢、不确定， 而且审计器自己也会判错——黑客松现场最怕这个。所以分两层：

L1 · 确定性层

词表与正则，现场必演

禁用词、敏感人物与事件、未标识的 AI 生成内容、数字日期职务这类硬事实。毫秒级、百分百可复现，现有代码改词表就能跑。

L2 · 判断层

模型复核，只标不拦

导向、语气、事实核查。输出「待人工复核」而不是「拦截」，主动承认不确定性，把人留在环里。时间不够就只做一个 case。

「审计器自己会错，所以高风险项只标不拦、必须人工终审」——这句话主动讲出来是加分的， 它说明我们懂内容行业的责任边界，而不是拿个模型当法官。

保密审计不要丢，降级成配角。 广电台自己也有机密——未播选题、采访对象联系方式、内部通稿。 现有的 PII 与密钥检测在这个场景里照样成立，博文已经写完、测试全绿的那部分不浪费。

行业依据

我们不发明流程，我们给现成流程装加速器

县级融媒体中心是 2018 年起整合县电视台、广播、报纸、新闻网、政务新媒体的产物， 机构性质是事业单位，归口县委宣传部管理。第一属性是宣传，不是内容生意。 所以「稿子出错」不是产品事故，是政治事故——这跟互联网公司的内容风控是两个量级的后果。

人的实况：人员结构老化、转隶来的多是「老广电人」、普遍推「一人多岗」、 一线记者编辑疲于应付时政报道。稿件生产是真痛点，不是硬凑的。

而它已经有一套跑了几十年的成文流程：

选题与派工 → 成稿 + 技术预检 → 初审 + 一校 → 复核修改 → 复审 + 二校 → 征求意见/会签 → 终审 + 三校 → 签发与电子签章 → 多平台发布 → 发布后巡查

「成稿 + 技术预检」这个节点是现成的，把关人就挂在这里——不用说服任何人改流程。

环节谁审什么我们怎么接
一校编辑/经办人错别字、语病、标点、格式L1 全自动
初审（一审）编辑/经办人文字、事实、规范L1 全自动
二校部门负责人数据、人名、地名、专业术语、排版一致性L1 + 少量 L2
复审（二审）部门负责人政策口径、事实核查、保密与隐私、发布价值L1 + 少量 L2

三校分管领导通读、排版效果、整体一致性留给人
台上这样讲

我们没有发明新流程。我们把三审三校里机械的那部分自动化了， 把判断的那部分留给人，并且让全程可追溯、责任到人。

系统

一条链路，六层，双向治理

01素材入口 粘贴 / 上传上级通稿、会议材料。不做采集对接。
→
02入口准入 判定这次调用该不该发生。硬拦 / 要理由 / 仅留痕三档。非法输入模型完全不碰。
→
03生产层 按本台风格生成播报稿 + 短视频文案。风格来自预置历史稿件 + 风格 skill。
→
04预检层 禁用词 / 领导表述 / 与原文一致性 / AI 标识。三档动作：拦截·标红·放行。
→
05三审流转 编辑 → 部门主任 → 分管领导。三个角色写死，一屏切换。
→
06审计层 每篇稿子一张 AI 参与度追溯图谱。谁写的、谁改的、谁签的。
架构硬约束：生产层调模型必须走把关人网关，业务代码不许直连。 这样审计天然全覆盖、零遗漏，博文已写好的 gateway / 护栏 / 策略 / 事件流 / 逐用户计量全部保住。 它同时是入口准入闸的强制力来源——绕不过网关，就绕不过准入。

预检层具体查什么（博文的 detector 规格）

  • 句级来源标记（卖点，优先级最高）——每句话带 ai / ai-edited / human / source 四种来源之一，流转时重算 AI 参与度。 词表打不过方正，句级来源只有站在生产现场才拿得到——这是唯一的结构性优势。
  • 禁用词与慎用词——新华社《新闻信息报道中的禁用词和慎用词》，2016 年 7 月修订版共 102 条，分时政社会生活、法律法规、民族宗教、港澳台与领土主权、国际关系五类。例：一般性会议不用「隆重召开」；报道领导活动慎用「亲自」；不称「中共 XX 省省委书记」应称「中共 XX 省委书记」；对国内领导干部和国企负责人不用「老板」。
  • 与原通稿的一致性比对——人名、职务、地名、数字、日期。生成稿里出现而原文没有的，一律标红。这是幻觉最容易致命的地方。
  • AI 生成内容标识——按《人工智能生成合成内容标识办法》自动补显式标识，并在文件元数据写隐式标识。
  • 三档动作沿用现有实现——block 拦下不让走、redact 标红待人工复核、flag 放行留痕。语义天然对应审片动作。
入口准入

唯一一档零成本的治理

输出侧拦截时，token 已经烧了、时间已经花了、模型已经生成了违规内容只是没给你看。 输入侧拦掉，什么都没发生——不烧钱、不留内容、不产生风险。这是整条链路上唯一免费的一档。

它答的还是另一个问题：公器私用。台里的 AI 账号被拿去写小说、写年终总结、生成不当内容—— 这不是内容合规问题，是纪律问题，而事业单位对这件事极其敏感。

代码是现成的：scanRequest() 这个入向钩子已经在 audit-gate 里跑着（当前做提示注入匹配），换判定逻辑即可，不是新架构。

必须分三档，不能一刀切

广电编辑的正常工作就是处理敏感题材。写事故通报、涉诉纠纷、涉政会议，输入里必然带敏感词。 一刀切拦掉，系统当场不可用——评委只要问一句「那我要报道这个事件怎么办」，方案就崩了。 所以复用现有的 block / redact / flag，重新定义语义：

档判定动作例
硬拦明确违法，且与新闻业务无关不给调用，模型完全不碰涉恐涉毒、色情赌博、诈骗话术、明确红线
要理由涉敏感题材，但可能是正当报道要求填选题依据 / 上级授权 → 留痕后放行事故、纠纷、涉政敏感事件
仅留痕正常业务里的常见敏感表述直接放行，进审计日常时政词汇
中间那档是这个设计里最值钱的部分

「要理由」证明我们懂新闻业务——不是拿通用内容安全套上来，而是知道敏感题材恰恰是这个行业每天在处理的东西。 人给个理由，系统留个痕，责任就落到人头上。这跟三审三校「把判断留给人」是同一个哲学。

另外单开一类：非业务用途识别。「帮我写篇小说」「写个年终总结」——不违法，但是公器私用。 这类用词表抓不到，要看用途；只标不拦、进审计报表，让台里管理者看得见。

别把它叫「敏感词过滤」

敏感词过滤是九十年代的东西，评委听了会归到很低的档位。叫「入口准入」—— 判定的不是词，是这次调用该不该发生。

竞品格局

这块地不是空白，三层都有人

层玩家做什么
采编发一体化平台拓尔思 TRS、中科大洋「快融」、新华智云（称已赋能 3000+ 媒体机构）、索贝策采编发评运屏全流程，含稿件统一撰写、审核、发布
智能审校方正智能审校、黑马校对、新华社「新华较真」、新华网勘误系统查错
AI 写稿快笔小新 (2015)、小封 (2017)、人民日报「创作大脑 AI+」(2023)生成稿件
坏消息：原 detector 规格撞了成熟商品

方正智能审校有 21 类 136 个词库，明确含领导人职务、领导人排序、 重要讲话、重要提法、禁用词慎用词、法律法规、敏感人物， 检查项直接写着「领导人姓名差错、领导人职务差错、领导人排序差错」；新华网勘误系统的 领导人姓名/职务/顺序勘误准确率 90%+；黑马校对 1995 年就在卖。 堆词表这条路走不通——我们 1 类打不过 21 类。

真正的空白：三层之间不通

采编发平台管流程，审校系统管成品，AI 写稿产品管生产——三者互不相通。 关键在于：审校系统拿到的永远是一篇「稿子」，它不知道这稿子是 AI 写的、AI 写了哪几句、 人改了多少、AI 是在什么提示下写出来的——因为这些产品全都诞生在 AI 写稿普及之前， 数据模型里根本没有「这句话是谁写的」这个字段。

我们的位置

不做审校（方正的地盘），不做采编平台（拓尔思、大洋的地盘）。 做的是把 AI 生产这个新变量接进已有的审校与三审体系，并补上它带来的新问题——责任归属。

台上主动承认，三句话

  • 「查错这件事，方正和黑马做了十年，做得比我们好，我们不做。」
  • 「但它们拿到的永远是一篇成品稿——不知道哪句是 AI 写的，不知道人改过没有，不知道谁放行的。」
  • 「因为它们诞生在 AI 写稿之前。我们补的是这一环。」

承认成熟品类再讲差异，可信度比假装空白高一个量级——而评委席里只要有一个媒体行业的人， 他一定知道方正智能审校。

县级台的真实条件，约束整个设计

  • 只有 46.8% 有独立机构番号，多数连行政归属都没解决
  • 「要设备没设备、要人没人、要钱没钱」
  • 「采编人员对新设备和新系统掌握不全面、使用不熟练」，技术支撑力量不足

新华智云 / 拓尔思 / 大洋那套是给省市级台的重型平台——县级台买不起、养不起、也用不好。 这就是「建而不用」的来源，也是我们对大洋的答法：不是功能比它多，是它那套县级台跑不起来。 业务流程因此定三条原则：一条路走到黑没有分支、预检只标注不阻断（硬拦除外）、留痕本身要有管理价值。

出彩点

AI 参与度追溯：别人做不到的那一块

《人工智能生成合成内容标识办法》2025 年 9 月 1 日施行，由国家网信办、工信部、公安部、国家广播电视总局四部门联合发布—— 广电总局自己就是签发方之一。所以「广电用 AI 生成的内容必须标识」不是我们编的合规需求，是它主管部门签的规章。

但办法只说「要标」，没人回答「一篇人机共同完成的稿子，AI 参与了多少、哪几句是它写的、终审有没有看过」。

而且它不只是合规记录，是管理指标：AI 参与度在每次流转时重算，人改得越多占比越低—— 所以一篇稿子若以 AI 参与度 100% 一路签发，说明三审三校形同虚设，没人真看过。 这是给台领导的抓手，方正和大洋给不了，因为它们不知道哪句是 AI 写的。

我们的系统天生知道，因为生产和审核在同一条链路上。每一篇签发的稿子都能给出一张图谱： 哪些句子 AI 原样保留、哪些人改过、哪些是人新写的、命中过哪些红线、被谁在哪一级放行、谁最终签发。

这一条同时答死两个质疑

「为什么不用现成的内容审核 API？」——因为它只看得见成品，看不见生产过程，给不出 AI 参与度。
「为什么不私有化部署就行了？」——私有化解决「模型在哪」，解决不了「哪句话是它写的、谁放行的」。

演示

三分钟，七个镜头

0:00
丢进一份真实通稿 县里的会议材料 / 政务通稿。一句话说清：这是县级台编辑每天上午都在干的活。
0:25
入口准入：两个对比 先演正当敏感题材——走「要理由」通道，编辑填了选题依据，放行留痕。 再演明显滥用「帮我写篇小说」——直接不给调用，模型一次都没被碰到。
0:50
一键生成播报稿 + 短视频文案 按本台风格。强调提速倍数——这是 AI 的主场，也是痛点所在。
1:20
预检自动标出三处 一处禁用词被拦下；一处数字与原通稿不符标红待复核；AI 标识自动补上。
1:55
走完三审三校 编辑改完提交 → 部门主任二审 → 分管领导终审签发。角色切换器一屏演完，不展开 OA 细节。
2:20
打开这篇稿子的追溯图谱 AI 参与度百分比、三处红线命中记录、两级放行、签发人与时间。这是全场最该停留的一屏。
2:50
对照组：关掉把关人再跑一遍 同一份通稿，禁用词直接就出去了，没有标识，没人知道是 AI 写的，出了事查不到人。
收口那句话

私有化解决不了这个，外挂的内容审核 API 也解决不了——因为它们都看不见生产过程。

边界

明确不做，并且写进作品说明

  • 内容采集对接——就是粘贴/上传，不做爬虫、不接任何外部系统。
  • 多平台发布——留个按钮，点了显示「已发布」。
  • 用户与权限体系——三个角色写死，不做账号管理。
  • 电子签章——不做。
  • 知识库不做 RAG 工程——预置十几篇本台历史稿件做风格参考即可。
  • L2 模型判断层——最多一个 case，且只标不拦。
为什么要主动写出来

黑客松作品被追问「这个是真的还是演的」是常态。主动划边界比被问出来强得多。 受控靶子与预置素材是演示环境，被问到如实说明。

合规

依据与一个必须澄清的点

  • 新华社《新闻信息报道中的禁用词和慎用词》——2016 年 7 月修订版新增 57 条、共 102 条，五大类。全行业事实标准，是预检层的主要词表来源。
  • 《人工智能生成合成内容标识办法》——2025 年 9 月 1 日施行，网信办 / 工信部 / 公安部 / 广电总局四部门联合发布。要求显式标识（文本首尾或中间提示、界面提示）+ 隐式标识（文件元数据）。
  • 《生成式人工智能服务管理暂行办法》——要求服务提供者对违法输入采取处置措施（含暂停/终止服务），是入口准入闸的法规依据。确切条款与施行日期上台前核原文。
  • 三审三校——行业通行制度，不是法规，但是每家融媒体中心的实际工作制度。
别在台上说错这一条

《广播电视安全播出管理规定》（广电总局令第 62 号）管的是技术性播出安全——停播、信号、设备故障， 事故分责任/技术/其它三类，特大/重大/一般三级。它不管内容差错。 内容侧的约束来自宣传纪律、三审制和禁用词规范，是另一套东西。 这两个混着讲，懂行的评委立刻能听出我们没进过这个行业。

风险与未决

还缺的三件，要盯的三条

还缺

  1. 赛道二评分细则（满分 100 的分项权重）。飞书手册 §三、§五在登出状态不渲染，一直没拿到。权重决定时间往哪投。
  2. 真实通稿素材。一份真实的县级政务通稿（脱敏）能把可信度抬一个量级。拿不到就自己编，但台上必须如实说明是模拟素材。
  3. 能问细节的广电真人。一个能打电话确认「你们一天几篇稿、三审卡在哪」的人，比任何调研都值钱。

要盯

  • 范围变更的时间成本。博文要重写 detectors 和 probe 两个文件，且必须他本人同意。这个决定拖过今晚就来不及了。
  • 法规名称与施行时间别在台上背错。上台前核一遍原文。讲错一个日期，整段合规论证的可信度就没了。
  • 「长期可维护」和「36 小时交付」是两件事。 目标不是这两天写出可维护的代码，是这个项目得能活下去、是真产品；这正是赛道二的取胜点。 但接下来 36 小时的工程取舍按 demo 的标准做——现有 CI 不覆盖 audit-gate、 它不走主应用的部署链路，这些是赛后要还的债，不是现在要修的。
