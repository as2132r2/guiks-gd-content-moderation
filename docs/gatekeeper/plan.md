**措辞纪律**

- **不说「安全」**——会被听成内容安全（易盾/天御那个红海），而且是防御性的。广电要的是**敢发、发得快、出了事说得清**。
- **不说「敏感词过滤」**——九十年代的技术印象。入口那层叫**「入口准入」**，判定的不是词，是这次调用该不该发生。
- **不说 AuditGate**——英文、技术词，对这个评委席先天弱一档。代码目录 `audit-gate/` 保持不动，赛后再改。
- **不假装审校是空白**——方正智能审校 21 类 136 个词库，黑马校对卖了三十年。主动承认，再讲我们看得见而它们看不见的那一面。详见 [market-landscape.md](market-landscape.md)。

给融媒体中心做一套**内容生产与监理系统**：AI 把稿件生产提速，全流程监控让提速出来的产能真的能发出去。
**监控是双向的**：进来的先过准入闸（非法输入直接不给调用模型），出去的过预检与三审。

**分工**：黄博文 = 网关 / 预检 / 审计（[PR #1209](https://github.com/juxiang-ai/bohe-ai-consultation/pull/1209) 的 `audit-gate/`）；William = 生产 / 三审流转 / 演示界面。
**时间**：组队表单 8/28 24:00（今天，先交）；作品 8/29 24:00。
**奖**：一等 1×¥15,000 / 二等 2×¥8,000 / 三等 3×¥4,000。

## 一、内核：三句话，因果闭环

> AI 让内容生产提速十倍，但三审三校的人力审核跟不上——提速的结果不是快，是审核堵死，或者放水出事故。
>
> 所以我们在同一条链路上做全流程监控：**把机械的校对自动化，把判断留给人，把每一步留痕。**
>
> 让 AI 提速出来的产能，真的能安全地发出去。

**为什么必须是因果，不能是并列。**「用 AI 辅助生产，*同时*做监控」撑不住——评委会问「那我能不能只要生产部分」。
只要两半能拆开卖，就还是两个产品。

| | 说法 | 后果 |
| --- | --- | --- |
| 并列（弱） | AI 辅助生产 **+** 全流程监控 | 监控是额外的一层安全，成本项，可砍可外购可换易盾 |
| 因果（强） | AI 提速 **→** 审核成瓶颈 **→** 必须自动化校对 | 监控是产能释放的前提，价值项，拆掉它 AI 提速不成立 |

台里原来一天五篇，三审审得过来；AI 让编辑一天出五十篇，审核当场成瓶颈。要么卡死（AI 白提速），要么放水（出事故）。
**监控的真正价值不是防止出错，是让审核跟得上生产的速度。**

**「安全」这个词不上台**：一是会被听成「内容安全」（易盾/天御那个红海），二是它是防御性的——广电最简单的防御是不用 AI。
广电要的是：**敢发、发得快、出了事说得清。**

## 四、核心错位：横向 vs 垂直

AuditGate 最漂亮的特征——改一行 `base_url` 接管任意 AI 产品——在这条赛道上是**结构性劣势**：行业无关，不落在六大产业里。

**「大模型与企业业务的结合」是主体，占分大头；「audit」不是并列的第二块，是这个主体「为什么能真上线」的答案。**

## 五、转向一（叙事）：回答「那为什么不用内部大模型」

现实比想象更不利：这些行业**早就在买私有化部署了**（智谱、DeepSeek、讯飞、华为昇腾；「数据不出域」是招标第一条）。
评委里有一个懂政企采购的，「防泄漏」这个卖点当场就没了。

### 私有化解决了「模型在哪」，没解决这四件

1. **数据不出域 ≠ 内部不越权，而且私有化让它更严重。** 内部模型接内部知识库后拥有全量数据读取权；
   传统权限体系在 RAG 面前失效——向量检索不认部门墙。泄密对象从「外部厂商」变成「自己人」，而后者没有现成系统在管。
2. **幻觉和内容违规不因为跑在内网就消失。** 播出出问题罚的是台，不管推理在哪台机器上；
   私有化受本地算力限制往往是参数更小、对齐更弱的版本，违规概率更高——这一项私有化是负分。
3. **「可追溯」本身是监管要求，私有化交付的是模型不是审计链路。** 谁在什么时间用什么 prompt 碰了哪些数据、
   输出被谁拿走——这套留痕得自己建，标里没有。合规责任压在服务提供者身上。
4. **真实形态不是「一个内部模型」，是一片影子 AI。** 一体机只管官方那条路，同时还有各部门自开的外部 API、
   办公套件自带助手、桌面工具、外包接进来的 SaaS。**治理点必须在流量层，不在模型层**——
   这才是「改一行 base_url 就接管」真正成立的地方。

**内部自用确实没人管，但输出会离开对话框。** 广电的产出要**播出去**，能源的要**进生产系统**，白酒的要**进配方和质检**。
输出一旦进入业务流程，责任全都回来了。**审计的锚点就在这一刻，和模型部署在哪毫无关系。**

**台上一句话**：私有化解决了「模型在哪」，没解决「模型被谁怎么用、说了什么、该不该说」。前者是采购问题，后者是治理问题。

## 六、转向二（审计对象）：从保密审计到适播审计

### 原来审的是什么（读代码得出）

- 入向 `scanRequest()`：匹配约 21 条提示注入词表（`忽略之前`/`开发者模式`/`解除限制`/`system prompt`/`原始指令`…），命中即 high 级 `injection`。
- 出向 `scanResponse()`：找**泄漏**——预埋服务密钥、系统提示词标记、内部机密（注释写「定价/工艺」）、银行卡号，再加正则扫手机号/身份证/银行卡。
- 行为：三档 `block`/`redact`/`flag`，按每企业策略配；redact 正则打码，block 换固定话术，放行清单降级为只留痕。
- probe 六类：`prompt-exfil`/`data-exfil`/`pii-dump`/`jailbreak`/`role-override`/`hallucination`；评分五维：可审计性/注入抵抗/数据合规/配置卫生/稳健性。

**一句话：这是「保密审计」，问的是「不该出来的东西出来了没有」。**

### 广电问的是「这段内容能不能播」

导向、事实准确、敏感人物与事件、AI 生成内容标识、版权、用词规范。**差别不是程度，是类别**——保密 vs 适播。

### 两层设计

- **L1 确定性层（现场必演）**：禁用词、敏感人物、未标识 AI 内容、数字日期职务等硬事实。毫秒级、可复现，现有代码改词表就能跑。
- **L2 判断层（只标不拦）**：导向、语气、事实核查。输出「待人工复核」，主动承认不确定性。时间不够只做一个 case。

「审计器自己会错，所以高风险项只标不拦、必须人工终审」——**主动讲出来是加分的**。

**保密审计降级保留**：广电台也有机密（未播选题、采访对象联系方式、内部通稿），博文写完并测试全绿的部分不浪费。

## 七、行业依据：三审三校

融媒体中心是 2018 年起整合广播电视台/报纸/新闻网/政务新媒体的产物，**事业单位，归口党委宣传部**。
第一属性是宣传不是内容生意——**稿子出错不是产品事故，是政治事故**。
人的实况：人员老化、多是「老广电人」、普遍「一人多岗」、一线记者编辑**疲于应付时政报道**。稿件生产是真痛点。

现成流程：

```
选题与派工 → 成稿 + 技术预检 → 初审 + 一校 → 复核修改 → 复审 + 二校
→ 征求意见/会签 → 终审 + 三校 → 签发与电子签章 → 多平台发布 → 发布后巡查
```

**「成稿 + 技术预检」这个节点是现成的，把关人就挂在这里**——不用说服任何人改流程。

| 环节 | 谁 | 审什么 | 我们怎么接 |
| --- | --- | --- | --- |
| 一校 | 编辑/经办人 | 错别字、语病、标点、格式 | L1 全自动 |
| 初审（一审） | 编辑/经办人 | 文字、事实、规范 | L1 全自动 |
| 二校 | 部门负责人 | 数据、人名、地名、术语、排版一致性 | L1 + 少量 L2 |
| 复审（二审） | 部门负责人 | 政策口径、事实核查、保密与隐私、发布价值 | L1 + 少量 L2 |
| 终审（三审） | 分管/主要领导 | **政治导向、社会效果、是否违法违规，决定发不发** | L2 只标不拦 |
| 三校 | 分管领导 | 通读、排版效果、整体一致性 | 留给人 |

**台上这样讲**：我们没有发明新流程。我们把三审三校里**机械的那部分**自动化了，把**判断的那部分**留给人，并且让全程可追溯、责任到人。

## 八、系统：一条链路，六层，双向治理

```
01 素材入口 → 02 入口准入 → 03 生产层 → 04 预检层 → 05 三审流转 → 06 审计层
```

1. **素材入口**——粘贴/上传上级通稿、会议材料。不做采集对接。
2. **入口准入**——判定这次调用该不该发生。硬拦 / 要理由 / 仅留痕三档。非法输入模型完全不碰。
3. **生产层**——按本台风格生成播报稿 + 短视频文案。风格来自预置历史稿件 + 风格 skill。
4. **预检层**——禁用词 / 领导表述 / 与原文一致性 / AI 标识。三档动作：拦截·标红·放行。
5. **三审流转**——编辑 → 部门主任 → 分管领导。三个角色写死，一屏切换。
6. **审计层**——每篇稿子一张 AI 参与度追溯图谱。谁写的、谁改的、谁签的。

> **架构硬约束**：生产层调模型**必须走把关人网关**，业务代码不许直连。
> 这样审计天然全覆盖、零遗漏，博文已写好的 gateway / 护栏 / 策略 / 事件流 / 逐用户计量全部保住。
> **它同时是入口准入闸的强制力来源**——绕不过网关，就绕不过准入。

### 入口准入：唯一一档零成本的治理

输出侧拦截时 token 已经烧了、时间已经花了、模型已经生成了违规内容只是没给你看。
**输入侧拦掉，什么都没发生**——不烧钱、不留内容、不产生风险。整条链路上唯一免费的一档。

它答的还是另一个问题：**公器私用**。台里的 AI 账号被拿去写小说、写年终总结——这不是内容合规问题，
是纪律问题，事业单位对这件事极其敏感。

代码现成：`scanRequest()` 入向钩子已经在 audit-gate 里跑着（当前做提示注入匹配），换判定逻辑即可，不是新架构。

**必须分三档，不能一刀切。** 广电编辑的正常工作就是处理敏感题材——写事故通报、涉诉纠纷、涉政会议，
输入里必然带敏感词。一刀切拦掉系统当场不可用，评委问一句「那我要报道这个事件怎么办」方案就崩了。
复用现有的 `block`/`redact`/`flag`，重新定义语义：

| 档 | 判定 | 动作 | 例 |
| --- | --- | --- | --- |
| **硬拦** | 明确违法，且与新闻业务无关 | **不给调用，模型完全不碰** | 涉恐涉毒、色情赌博、诈骗话术、明确红线 |
| **要理由** | 涉敏感题材，但可能是正当报道 | 要求填选题依据/上级授权 → 留痕后放行 | 事故、纠纷、涉政敏感事件 |
| **仅留痕** | 正常业务里的常见敏感表述 | 直接放行，进审计 | 日常时政词汇 |

**中间那档是最值钱的部分。**「要理由」证明我们懂新闻业务——不是拿通用内容安全套上来，
而是知道**敏感题材恰恰是这个行业每天在处理的东西**。人给个理由，系统留个痕，责任落到人头上。
这跟三审三校「把判断留给人」是同一个哲学。

**另外单开一类：非业务用途识别。**「帮我写篇小说」「写个年终总结」——不违法但是公器私用，
词表抓不到、要看用途；只标不拦、进审计报表，让台里管理者看得见。

> **别把它叫「敏感词过滤」**。那是九十年代的东西，评委听了会归到很低的档位。
> 叫**「入口准入」**——判定的不是词，是**这次调用该不该发生**。

### 预检层查什么（博文的 detector 规格）

> **规格重点已调整**：不要堆词表数量——方正智能审校有 21 类 136 个词库（含领导人职务、领导人排序、
> 禁用词慎用词、敏感人物），我们堆不过。词表仍要有（demo 必须演出拦截效果），但它是**配角**。
> **卖点是句级来源标记**（这句是 AI 原样 / 人改过 / 人新写 / 原文引用）及其衍生的 AI 参与度——
> 那是只有站在生产现场才拿得到的数据。详见 [market-landscape.md](market-landscape.md)。

- **句级来源标记**（新增，卖点）——每句话带 `ai` / `ai-edited` / `human` / `source` 四种来源之一，
  流转时重算 AI 参与度。见 [business-process.md](business-process.md) 第四节。
- **禁用词与慎用词**——新华社《新闻信息报道中的禁用词和慎用词》2016 年 7 月修订版共 102 条，五大类。
  例：一般性会议不用「隆重召开」；报道领导活动慎用「亲自」；不称「中共 XX 省省委书记」应称「中共 XX 省委书记」；对国内领导干部和国企负责人不用「老板」。
- **与原通稿的一致性比对**——人名、职务、地名、数字、日期。生成稿里有而原文没有的一律标红。幻觉最致命的地方。
- **AI 生成内容标识**——按《标识办法》自动补显式标识，文件元数据写隐式标识。
- **三档动作沿用现有实现**——`block` 拦下不让走、`redact` 标红待人工复核、`flag` 放行留痕。

## 九、出彩点：AI 参与度追溯

《人工智能生成合成内容标识办法》2025 年 9 月 1 日施行，由**网信办、工信部、公安部、国家广播电视总局四部门联合发布**——
广电总局自己就是签发方之一。所以「广电用 AI 生成内容必须标识」不是我们编的，是主管部门签的规章。

但办法只说「要标」，**没人回答「一篇人机共同完成的稿子，AI 参与了多少、哪几句是它写的、终审有没有看过」**。

我们的系统天生知道，因为生产和审核在同一条链路上：哪些句子 AI 原样保留、哪些人改过、哪些是人新写的、
命中过哪些红线、被谁在哪一级放行、谁最终签发。

**这一条同时答死两个质疑**：
- 「为什么不用现成的内容审核 API？」——它只看得见成品，看不见生产过程，给不出 AI 参与度。
- 「为什么不私有化部署就行了？」——私有化解决「模型在哪」，解决不了「哪句话是它写的、谁放行的」。

## 十三、边界：明确不做，并写进作品说明

- **内容采集对接**——就是粘贴/上传，不做爬虫、不接外部系统
- **多平台发布**——留个按钮，点了显示「已发布」
- **权限配置界面**——账号与角色做（登录、会话、四个角色），但**角色↔权限是代码内写死的固定组合**，
  不做权限管理后台。一个账号可持有多个角色，对应中小型融媒体中心「一人多岗」的实况
- **电子签章**——不做
- **知识库不做 RAG 工程**——预置十几篇本台历史稿件做风格参考
- **L2 模型判断层**——最多一个 case，且只标不拦

> **2026-08-29 修订**：原先这里写的是「用户与权限体系——三个角色写死」，即完全不做。
> 现改为做账号 · 角色 · 权限的**固定组合版**（[requirements.md](requirements.md) 7.12–7.25）。
> 对外口径要跟着改：**不说「做了完整权限体系」，说「做了账号与固定角色组合，权限配置界面不做」。**

黑客松被追问「这是真的还是演的」是常态，**主动划边界比被问出来强得多**。受控靶子与预置素材是演示环境，被问到如实说明。

## 十四、合规依据与一个必须澄清的点

- **新华社《新闻信息报道中的禁用词和慎用词》**——2016 年 7 月修订版新增 57 条、共 102 条，五大类。行业事实标准，预检层主要词表来源。
- **《人工智能生成合成内容标识办法》**——2025-09-01 施行，网信办/工信部/公安部/**广电总局**四部门联合发布。显式标识 + 隐式标识（文件元数据）。
- **《生成式人工智能服务管理暂行办法》**——要求服务提供者对违法输入采取处置措施（含暂停/终止服务），是入口准入闸的法规依据。**确切条款与施行日期上台前核原文。**
- **三审三校**——行业通行制度，不是法规，但是每家融媒体中心的实际工作制度。

> **别在台上说错**：《广播电视安全播出管理规定》（广电总局令第 62 号）管的是**技术性播出安全**——停播、信号、设备故障，
> 事故分责任/技术/其它三类，特大/重大/一般三级。**它不管内容差错。** 内容侧约束来自宣传纪律、三审制和禁用词规范，是另一套东西。
> 混着讲，懂行的评委立刻能听出我们没进过这个行业。
