## 演示前检查单（D.7）

### 环境

- [ ] **只启一个服务占 3300**——容器和 `npm run dev` 会抢端口。二选一：
  ```bash
  docker compose down          # 用 dev server 时
  # 或
  docker compose up -d         # 用容器时，先确认 dev server 已停
  ```
- [ ] `curl http://localhost:3300/readyz` 返回 `{"status":"ready"}`
- [ ] 确认上游模式：`curl http://localhost:3300/api/meta` 看 `"model"` 字段
  - `"mock"` = 内置确定性 mock，**彩排与保底用这个**
  - `"configured"` = 真实模型，内容更真但**依赖网络、可能超时**
- [ ] 在普通工作台点「演示模式」，显示档默认选「低清投影」；LED 大屏再显式切换
- [ ] 在准备面板点「重建三组样例」，看到「已重建 3 组准入样例」后再进入演示
- [ ] 进入后应直接停在空白投料页；此刻再开始三分钟计时

### 浏览器

- [ ] 浏览器缩放 100%；按会场设备选择「低清投影 / LED 大屏」，需要时再点演示顶栏「全屏」
- [ ] 1024×768 以上应看到完整六道闸门、三段解释和首屏推荐动作；不得横向滚动
- [ ] 关掉其他标签页与通知
- [ ] **预备好改稿的两句话**（[source-notice.md](source-notice.md) 方案二），放剪贴板或第二屏

### 内容核对

实跑一遍主通稿，核对这几个数字——**它们是口播里要报出来的**：

| 位置 | 应为 |
| --- | --- |
| 生成后 | 9 句，AI 参与度 100% |
| 预检 | 拦下 1 · 标红 2 · 留痕 1 |
| 改两句后 | AI 参与度 **88.9%**，预检 拦下 0 · 标红 1 · 留痕 0 |

**词表或 mock 一改，这些数字就会变。** 改完必须重跑核对。

## 应急预案（D.10）

### ① 模型超时或报错

**征兆**：点「生成播报稿与短视频文案」后转圈超过 5 秒。

**处置**：切回内置 mock，**15 秒恢复，演示内容完全一致**。

```bash
# .env 里清空 UPSTREAM_URL，然后
docker compose up -d --force-recreate     # 容器
# 或直接重启 npm run dev
```

> **彩排和正式演示都建议直接用 mock。** 它是确定性的——同一份通稿永远得到同一个结果，
> 上面那张数字核对表才成立。真实模型留给「接得通」这个论证，不必在三分钟里演。

### ② 库里数据脏了

**征兆**：左栏列表出现重复标题、或状态不对。

**处置**：点「演示准备（重置并建样例）」。命令行等价：

```bash
curl -X POST http://localhost:3300/api/demo/seed
```

**注意**：这会清空全部稿件。演示中途误点会丢掉正在走的那一篇，需要重走。

### ③ 端口被占

**征兆**：页面打不开，或打开的是旧版本。

**处置**：容器和 dev server 只能留一个。

```bash
docker compose down
```

### ④ 会场没网

**处置**：不用处置。页面零外部资源（无 CDN、无网络字体、无远程图片），
mock 上游在进程内——**整条演示路径不依赖网络**，已实测。

前提是**别切真实模型**。

### ⑤ 三分钟不够

**砍镜头，不要压缩讲解。** 语速一快，评委什么都记不住。

砍的顺序（从后往前砍价值最低的）：
1. 0:25 那一镜的第三档「公器私用」——省 15 秒
2. ⑤ 三审三校压到只切一次角色——省 10 秒
3. **⑥ 追溯和 ⑦ 对照组一秒都不能砍**，那是全场唯一别人做不出来的两屏
