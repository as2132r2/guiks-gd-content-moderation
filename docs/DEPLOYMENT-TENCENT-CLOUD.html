腾讯云原生部署运行手册

适用项目：guiks-gd-content-moderation。采用 Node.js + systemd + Nginx，不运行 Docker。应用只监听本机 127.0.0.1:3300，公网由 Nginx 转发。

当前是比赛临时公开 Demo：使用 HTTP 80 和真实模型，不承载真实业务数据。比赛结束后应停服或改为 Mock；若转为正式业务，必须启用域名 HTTPS 并完成适用的备案与合规流程。

1. 资源与网络基线

项目生产建议

2. 服务器初始化

sudo apt-get update
sudo apt-get install -y nginx curl ca-certificates
# 安装受支持的 Node.js 22；部署前以 node --version 确认。
sudo useradd --system --home /opt/guiks-gd-content-moderation --shell /usr/sbin/nologin guiks
sudo install -d -o guiks -g guiks -m 0750 /opt/guiks-gd-content-moderation/releases
sudo install -d -o guiks -g guiks -m 0750 /var/lib/guiks-gd-content-moderation
sudo install -d -o root -g guiks -m 0750 /etc/guiks-gd-content-moderation

应用构建在 CI 或受控发布机执行：npm ci、npm run check、npm run build、npm prune --omit=dev。只上传 dist/、生产 node_modules/ 和必要的包清单，使用 Git SHA 作为发布目录名。

3. 密钥、模型与账号

从 deploy/app.env.example 复制到服务器 /etc/guiks-gd-content-moderation/app.env，以 root:guiks、0640 保存。该文件包含模型 Key，不可上传仓库、不可写入 systemd unit、不可回显到日志。

含空格的值必须加单引号。UPSTREAM_PROFILES_JSON 是一行 JSON，写成 KEY={...} 不加引号时 systemd 能解析，但任何用 source 读这个文件的运维脚本都会拿到被空格截断的值，报 UPSTREAM_PROFILES_JSON must be valid JSON 直接崩。正确写法：UPSTREAM_PROFILES_JSON='[{...}]'。
生产必须分别生成 SESSION_SECRET 与 GATEWAY_TOKEN，均为不同的 base64: + 至少 32 随机字节。设置 APP_MODE=production、ALLOW_MOCK_UPSTREAM=false，并配置至少一个真实模型档。

多模型通过 UPSTREAM_PROFILES_JSON 注入。DeepSeek 使用 thinking=disabled；GLM-5.3 / GLM-5.3-Flash 必须使用 thinking=provider-default。应用不会把 URL 或 Key 返回给浏览器。

首次启动后创建生产账号：sudo -u guiks /usr/bin/node /opt/guiks-gd-content-moderation/current/dist/provision-user.js --username news-editor --display-name "生产编辑" --roles editor。使用交互隐藏输入；不可用 --password。

4. systemd 与 Nginx

将仓库中的 deploy/guiks-gd-content-moderation.service 复制到 /etc/systemd/system/；将 Nginx 模板替换域名和证书路径后放到 /etc/nginx/sites-available/ 并启用。执行 nginx -t 后 reload。证书可由腾讯云 SSL 控制台或 ACME 获取，续期必须纳入运维日历。

sudo systemctl daemon-reload
sudo systemctl enable --now guiks-gd-content-moderation
curl --fail http://127.0.0.1:3300/readyz
sudo nginx -t && sudo systemctl reload nginx
curl --fail https://YOUR_DOMAIN/readyz

4.5 播种与清理试用数据

部署完代码，库还是空的。播种脚本就是全部，不需要另外准备什么。

REAL=$(readlink -f /opt/guiks-gd-content-moderation/current)
sudo -u guiks bash -c "set -a; . /etc/guiks-gd-content-moderation/app.env; set +a;   UPSTREAM_PROFILES_JSON= UPSTREAM_URL= ALLOW_MOCK_UPSTREAM=true   node $REAL/dist/seed-demo.js"

三个环境变量覆盖只作用于这一个进程，app.env 不动，服务重启后照常用真实模型。

为什么播种走 mock。内置 mock 是确定性的，同一份通稿永远得到同一个结果——试用手册里写的每个数字才对得上。 真实模型的输出不可复现，手册第 3、4 步那几个教学点（禁用词被拦、数字与原通稿不一致）就不保证出现。 真实模型的能力留给试用者现场新建稿件去验证，那才是真调用。
播种只增不删。按标题判重，已播过的跳过，试用者自己建的稿子一概不动；重复跑一次是空操作。 要推倒重来必须显式清理：node $REAL/dist/reset-demo.js --yes（删全部稿件与留痕，账号保留）。 播种和删除是两件事——试用者建的稿子和播种数据在同一个库里，播种顺手清库，别人试到一半的东西就没了。

预期输出的最后一行：完成：全库稿件 15 篇，已签发 10，留痕 315 条，全台 AI 参与度 95.0%。 这是空库首播的结果；库里本来有数据，这一行自然更大——它报的是全库现状，不是这次播了多少。

清理或播种之前先备份：

sudo -u guiks node -e "
const D=require('$REAL/node_modules/better-sqlite3');
new D('/var/lib/guiks-gd-content-moderation/app.db',{readonly:true})
  .backup('/var/lib/guiks-gd-content-moderation/backups/app-'+Date.now()+'.db')
  .then(()=>process.exit(0));"

账号五个（zhangmin / lijianguo / wangzhiyuan / stationadmin / chenxue）， 口令取 SEED_PASSWORD，默认 gatekeeper-demo，已存在就跳过、不覆盖改过的口令。 详见 docs/deploy/operations.md 与 docs/deploy/user-manual.md。

5. 发布、验证与回滚

  1. 检查工作树、测试和构建通过。
  2. 先执行 SQLite 逻辑备份，再创建云盘快照。
  3. 上传新 SHA 到 releases/<sha>，用原子软链接更新 current。
  4. 重启 systemd，检查 /readyz、HTTPS 登录、一个授权工作流与模型调用。
  5. 异常时将 current 指回上一个 SHA、重启服务；数据问题再按备份或快照恢复。

6. 备份与监控

每日执行 SQLite 一致性逻辑备份并上传 COS，保留至少 30 天；云盘自动快照保留 7–14 天。告警项：/readyz 非 200、systemd 服务失败、磁盘大于 80%、内存压力、连续 5xx、模型 429/502 与证书到期。

7. 当前 Demo 运维要点

  • 安全组仅需公开 TCP 80；TCP 3300 不公开，SSH 22 应限制为运维 IP。
  • 服务检查：sudo systemctl status guiks-gd-content-moderation；就绪检查：curl http://127.0.0.1:3300/readyz。
  • 当前公开 Demo 使用真实模型，任何登录用户的生成都可能消耗模型额度；比赛结束后应停用服务或设置 ALLOW_MOCK_UPSTREAM=true 后重启服务。
  • 禁止将 app.env、SSH 私钥、模型 Key、网关 Token 或管理员密码提交到仓库、截图或日志。
